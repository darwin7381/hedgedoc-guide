## ⚡ 快速開始（3 步驟）

### 步驟 1：下載並匯入範本

**方法 A**：從本地文件匯入
1. 打開 `workflows/hedgedoc-create-and-read-template.json`
2. 複製全部內容
3. 在 n8n 中：右上角「⋯」→「Import from File」
4. 貼上 JSON 內容 → 點擊「Import」

**方法 B**：使用 curl 下載
```bash
curl -o hedgedoc-workflow.json \
  https://raw.githubusercontent.com/darwin7381/hedgedoc-guide/main/workflows/hedgedoc-create-and-read-template.json
```

**方法 C**：直接從 URL 匯入（最快）
1. 在 n8n 中：右上角「⋯」→「Import from URL」
2. 貼上 Raw URL
3. 點擊「Import」

### 步驟 2：設置你的 Token

找到 **「Content Parameter」** 節點：
1. 點擊節點打開編輯
2. 找到 `token_manager_key` 欄位
3. 將 `YOUR_TOKEN_HERE` 改為你的 Token

**推薦方式**（使用環境變數）：
```javascript
={{ $env.HEDGEDOC_TOKEN }}
```

### 步驟 3：執行測試

1. 點擊「**Execute workflow**」
2. 查看結果 ✅

**完成！** 🎉

## 📝 範本說明

### 功能清單

- ✅ 透過 Token Manager Gateway 創建 HedgeDoc 筆記
- ✅ 自動提取 Note ID
- ✅ 生成所有訪問 URL（編輯、雙開、只讀等）
- ✅ 讀取筆記內容
- ✅ 獲取筆記元數據

### Workflow 結構

```
[Manual Trigger] - 手動觸發
     ↓
[Content Parameter] - 設置 Token 和筆記內容
     ↓
[創建筆記] - POST /new（已設置正確的 redirect 處理）
     ↓
[整理新 markdown 文件輸出參數] - 提取 Note ID 和生成各種 URL
     ↓
     ├─ [讀取 markdown 文件內容] - GET /download
     ├─ [讀取元數據] - GET /info
     └─ [各版本 view] - 整理編輯/預覽 URLs
```

### 包含的節點（共 7 個）

1. **Manual Trigger** - 手動觸發
2. **Content Parameter** - 設置 Token 和內容
3. **創建筆記** - POST /new（已設置正確的 redirect 處理）
4. **整理新 markdown 文件輸出參數** - 提取 Note ID 和生成 URLs
5. **讀取 markdown 文件內容** - GET /download
6. **讀取元數據** - GET /info
7. **各版本 view** - 整理編輯/預覽 URLs

```json
{
  "noteId": "AQY5Z-KpQxyoK4JAOtTfcw",
  
  // Gateway URLs（透過 Token Manager）
  "gatewayUrl": "https://api-gateway.cryptoxlab.workers.dev/api/hedgedoc/AQY5Z-KpQxyoK4JAOtTfcw",
  "downloadUrl": "https://api-gateway.cryptoxlab.workers.dev/api/hedgedoc/AQY5Z-KpQxyoK4JAOtTfcw/download",
  "infoUrl": "https://api-gateway.cryptoxlab.workers.dev/api/hedgedoc/AQY5Z-KpQxyoK4JAOtTfcw/info",
  
  // 直接訪問 HedgeDoc URLs
  "directUrl": "https://hedgedoc.example.com/note-id",
  "editUrl": "https://hedgedoc.example.com/note-id?edit",
  "bothUrl": "https://hedgedoc.example.com/note-id?both",
  "viewUrl": "https://hedgedoc.example.com/note-id?view",
  
  "createdAt": "2025-11-09T10:15:33.123Z"
}
```

### URL 用途說明

| URL 類型 | 用途 | 何時使用 |
|---------|------|---------|
| `noteId` | 筆記 ID | 用於後續 API 調用 |
| `gatewayUrl` | Gateway 訪問 | 需要透過 Token Manager 訪問時 |
| `downloadUrl` | 下載 Markdown | 需要純文字內容時 |
| `infoUrl` | 獲取元數據 | 需要標題、時間等資訊時 |
| `directUrl` | 直接網頁訪問 | 分享給他人查看（預設模式） |
| `editUrl` | 整頁編輯模式 | 需要專注編輯時 |
| `bothUrl` | 雙開編輯模式 | 需要邊寫邊看預覽時 |
| `viewUrl` | 只讀模式 | 只需查看不需編輯時 |

## 🔧 範本設置詳解

### 必須設置的選項

**在「創建筆記」節點的 Options 中**：

```
Redirects:
  ☐ Follow Redirects (必須關閉)

Response:
  ☑ Include Response Headers and Status (必須開啟)
  ☑ Never Error (必須開啟)
```

**這些設置已包含在範本中**，但如果你修改了節點，請確保這些選項正確。

### 為什麼需要這些設置？

| 設置 | 作用 | 不設置的後果 |
|------|------|-------------|
| Follow Redirects = OFF | 不自動跟隨 redirect | 返回 HTML 頁面 |
| Include Response Headers and Status = ON | 返回完整響應（包含 headers） | 無法提取 Location |
| Never Error = ON | 允許非 2xx 狀態碼 | 302 被視為錯誤 |

## ⚠️ 常見錯誤與解決

### 錯誤 1：返回 HTML 頁面

**症狀**：
```json
{
  "statusCode": 200,
  "data": "<!DOCTYPE html>..."
}
```

**原因**：Follow Redirects 沒有關閉

**解決**：
1. 打開「創建筆記」節點
2. 滾動到 Options → Redirects
3. 確認 Follow Redirects = **OFF**（灰色開關）

---

### 錯誤 2：顯示 302 錯誤

**症狀**：
```
NodeApiError: 302 - "Found. Redirecting to..."
```

**原因**：Never Error 沒有啟用

**解決**：
1. 打開「創建筆記」節點
2. 滾動到 Options → Response
3. 確認 Never Error = **ON**（綠色開關）

---

### 錯誤 3：Code 節點報錯

**症狀**：
```
Cannot read property 'location' of undefined
```

**原因**：Include Response Headers and Status 沒有啟用

**解決**：
1. 打開「創建筆記」節點
2. 滾動到 Options → Response
3. 確認 Include Response Headers and Status = **ON**（綠色開關）

---

### 錯誤 4：401 Unauthorized

**症狀**：
```json
{
  "error": "Invalid API Key"
}
```

**原因**：Token 無效或未設置

**解決**：
1. 檢查「Content Parameter」節點的 `token_manager_key`
2. 確認 Token 有效（到 Token Manager 檢查）
3. 確認 Token 的 Scopes 包含 `hedgedoc` 或 `*`

---

### 錯誤 5：匯入後所有節點都是紅色

**症狀**：所有節點顯示錯誤圖標

**原因**：節點類型不相容或 n8n 版本太舊

**解決**：
1. 確認 n8n 版本 >= 1.0.0
2. 更新 n8n 到最新版本
3. 或參考 [n8n-setup-guide.md](../n8n-setup-guide.md) 手動創建

---

### 錯誤 6：curl 可以但 n8n 不行

**症狀**：終端機 curl 測試成功，但 n8n 失敗

**原因**：
- curl `-i` 不跟隨 redirect
- n8n 預設跟隨 redirect

**解決**：
- 確認範本中的 Options 設置正確
- 或查看 [04-troubleshooting/4.4-n8n-hedgedoc-redirect-issue.md](../04-troubleshooting/4.4-n8n-hedgedoc-redirect-issue.md)

## 🔍 節點詳細說明

### 節點 1：Manual Trigger

**類型**：Manual Trigger  
**作用**：手動觸發 workflow  
**設置**：無需設置

---

### 節點 2：Content Parameter

**類型**：Set  
**作用**：設置 Token 和筆記內容

**設置**：
```javascript
{
  "Markdown Article": "=# 測試筆記標題\n\n## 測試時間\n{{ $now }}\n\n...",
  "token_manager_key": "YOUR_TOKEN_HERE"  // ← 需要修改這裡
}
```

**需要修改**：
- `token_manager_key` - 改為你的 Token
- `Markdown Article` - 改為你要創建的內容（可選）

---

### 節點 3：創建筆記

**類型**：HTTP Request  
**作用**：調用 Gateway API 創建筆記

**設置**：
```
Method: POST
URL: https://api-gateway.cryptoxlab.workers.dev/api/hedgedoc/new

Headers:
  X-API-Key: ={{ $json.token_manager_key }}
  Content-Type: text/markdown

Body:
  Send Body: ON
  Body Content Type: Raw/JSON
  Content: ={{ $json['Markdown Article'] }}

Options（關鍵！）:
  Redirects:
    ☐ Follow Redirects (關閉)
  
  Response:
    ☑ Include Response Headers and Status (開啟)
    ☑ Never Error (開啟)
```

**輸出**：
```json
{
  "statusCode": 302,
  "headers": {
    "location": "https://api-gateway.cryptoxlab.workers.dev/api/hedgedoc/xxx"
  }
}
```

---

### 節點 4：整理新 markdown 文件輸出參數

**類型**：Code  
**作用**：從 Location header 提取 Note ID 和生成所有 URLs

**代碼**：
```javascript
// 從 HTTP Response 的 headers 中提取 location
const location = $input.item.json.headers.location;

// 從 URL 中提取 Note ID（最後一段）
const noteId = location.split('/').pop();

// 構建不同格式的 URL
return {
  noteId: noteId,
  
  // Gateway URLs（透過 Token Manager）
  gatewayUrl: location,
  downloadUrl: `${location}/download`,
  infoUrl: `${location}/info`,
  
  // 直接訪問 HedgeDoc URLs
  directUrl: `https://hedgedoc.example.com/${noteId}`,
  editUrl: `https://hedgedoc.example.com/${noteId}?edit`,      // 整頁編輯模式
  bothUrl: `https://hedgedoc.example.com/${noteId}?both`,      // 雙開編輯模式
  viewUrl: `https://hedgedoc.example.com/${noteId}?view`,      // 只讀模式
  
  // 其他資訊
  createdAt: new Date().toISOString()
};
```

**輸出**：見上方「範本輸出說明」章節

---

### 節點 5：讀取 markdown 文件內容

**類型**：HTTP Request  
**作用**：讀取剛創建的筆記 Markdown 內容

**設置**：
```
Method: GET
URL: ={{ $json.downloadUrl }}

Headers:
  X-API-Key: ={{ $('Content Parameter').item.json.token_manager_key }}
```

**輸出**：完整的 Markdown 文字內容

```

{
  "title": "測試筆記標題",
  "description": "...",
  "viewcount": 0,
  "createtime": "2025-11-09T...",
  "updatetime": null
}
```

**解決**：
1. 檢查「創建筆記」節點
2. 確認 "Include Response Headers and Status" = ON
3. 執行後檢查輸出是否包含 `headers.location`

**Debug 方法**：
```javascript
// 在 Code 節點開頭添加
console.log('Input:', JSON.stringify($input.item.json, null, 2));

// 檢查 location 是否存在
if (!$input.item.json.headers || !$input.item.json.headers.location) {
  throw new Error('Location header not found');
}
```

### 問題：執行時間過長

**症狀**：workflow 執行超過 10 秒

**原因**：
1. 速率限制（HedgeDoc 限制 20 次/時間窗口）
2. 網路延遲
3. Gateway 響應慢

**解決**：
1. 添加 Wait 節點（避免速率限制）
2. 設置 Retry on Fail
3. 檢查 Gateway 狀態：https://token.example.com/system-health

### 問題：範本無法在不同 n8n 環境使用

**症狀**：在另一個 n8n 實例中匯入失敗

**原因**：環境變數或設置不同

**解決**：
1. 確認目標環境有設置 `HEDGEDOC_TOKEN` 環境變數
2. 或在「Content Parameter」節點直接填入 Token
3. 檢查 n8n 版本是否相容（>= 1.0.0）

// 在 Content Parameter 之前添加 Code 節點

// 從 HTTP Response 的 headers 中提取 location
const location = $input.item.json.headers.location;

const noteId = location.split('/').pop();
