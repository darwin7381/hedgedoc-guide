# n8n + HedgeDoc Redirect 問題完整解決方案

**問題狀態**：✅ 已解決  
**影響範圍**：所有使用 n8n 調用 HedgeDoc API 的場景  
**解決日期**：2025-11-09

---

## 📋 問題摘要

在 n8n 中調用 HedgeDoc API（透過 Token Manager Gateway）創建筆記時，返回的不是預期的 302 redirect，而是 HTML 頁面內容或錯誤訊息。

---

## 🐛 問題現象

### 現象 1：返回 HTML 頁面

**症狀**：
```json
{
  "statusCode": 200,
  "data": "<!DOCTYPE html>\n<html>\n<head>\n<title>HedgeDoc</title>..."
}
```

**預期結果**：
```json
{
  "statusCode": 302,
  "headers": {
    "location": "https://api-gateway.cryptoxlab.workers.dev/api/hedgedoc/abc123"
  }
}
```

### 現象 2：返回錯誤訊息

**症狀**：
```
NodeApiError: 302 - "Found. Redirecting to https://hedgedoc.example.com/..."
Problem in node 'HTTP Request'
```

**截圖證據**：
- 錯誤顯示 `302 - "Found. Redirecting to ..."`
- n8n 將 302 視為錯誤而非正常響應

---

## 🔍 根本原因分析

### 問題層級

這個問題涉及**兩個獨立的層級**：

#### 層級 1：Gateway Worker（已解決）

**問題**：
- Cloudflare Worker 無法處理 `POST + Request Body + 302 Redirect`
- 原因：`request.body` 是 ReadableStream（單次使用）
- Fetch API 預設跟隨 redirect，但 stream 無法重新發送

**解決方案**（在 Worker 代碼中）：
```javascript
// 將 body 轉成可重複使用的 buffer
const requestInit = {
  method: request.method,
  headers: request.headers,
  redirect: 'manual',  // 不自動跟隨 redirect
  body: request.body ? await request.arrayBuffer() : undefined
};
```

**狀態**：✅ 已由 Core Team 在 Gateway Worker 中修復

#### 層級 2：n8n 客戶端（需要用戶設置）

**問題**：
- n8n HTTP Request 節點預設會自動跟隨 redirect
- n8n 將非 2xx 狀態碼視為錯誤

**行為對比**：

| 工具 | 預設行為 | 結果 |
|------|---------|------|
| `curl -i` | 顯示 302，不跟隨 | ✅ 看到 Location header |
| `n8n` (預設) | 自動跟隨 redirect | ❌ 返回目標頁面的 HTML |
| `n8n` (設置後) | 不跟隨，接受 3xx | ✅ 看到 Location header |

**發生流程**（預設情況）：
```
1. n8n 發送: POST /api/hedgedoc/new
2. Gateway 返回: 302 Found + Location: /abc123
3. n8n 自動跟隨: GET /api/hedgedoc/abc123
4. HedgeDoc 返回: 200 OK + HTML 頁面
5. n8n 顯示: HTML 內容（不是我們要的）
```

**正確流程**（設置後）：
```
1. n8n 發送: POST /api/hedgedoc/new
2. Gateway 返回: 302 Found + Location: /abc123
3. n8n 停止，不跟隨 redirect
4. n8n 返回: 302 + headers.location
5. 用戶可以提取 Note ID
```

## ✅ 完整解決方案

### 步驟 1：確認 Gateway 已更新

**檢查方式**：在終端機測試
```bash
curl -X POST https://api-gateway.cryptoxlab.workers.dev/api/hedgedoc/new \
  -H "X-API-Key: your_token" \
  -H "Content-Type: text/markdown" \
  -d "# Test" \
  -i
```

**預期結果**：
```
HTTP/2 302
location: https://api-gateway.cryptoxlab.workers.dev/api/hedgedoc/abc123
```

如果看到這個，Gateway 工作正常 ✅

### 步驟 2：在 n8n 中設置 HTTP Request 節點

#### 2.1 基本設置

```
Method: POST
URL: https://api-gateway.cryptoxlab.workers.dev/api/hedgedoc/new
Authentication: None
```

#### 2.2 Headers

```
Name: X-API-Key
Value: {{$env.HEDGEDOC_TOKEN}}

Name: Content-Type
Value: text/markdown
```

#### 2.3 Body

```
Send Body: ON
Body Content Type: Raw/JSON
Body: （你的 Markdown 內容）
```

#### 2.4 Options（🔥 關鍵設置）

**必須設置以下三個選項**：

```
Redirects 區塊：
  ☐ Follow Redirects (關閉 - 灰色)

Response 區塊：
  ☑ Include Response Headers and Status (開啟 - 綠色)
  ☑ Never Error (開啟 - 綠色)
```

**為什麼需要這些設置**：

| 設置 | 作用 | 不設置的後果 |
|------|------|-------------|
| Follow Redirects = OFF | 不自動跟隨 redirect | 返回 HTML 頁面 |
| Include Response Headers and Status = ON | 返回完整響應（包含 headers） | 無法提取 Location |
| Never Error = ON | 允許非 2xx 狀態碼 | 302 被視為錯誤 |

### 步驟 3：提取 Note ID

添加 **Code** 節點：

```javascript
// 從 HTTP Response 中提取 location
const location = $input.item.json.headers.location;

// 提取 Note ID（URL 的最後一段）
const noteId = location.split('/').pop();

// 返回結構化數據
return {
  noteId: noteId,
  noteUrl: location,
  directUrl: `https://hedgedoc.example.com/${noteId}`
};
```

**輸出**：
```json
{
  "noteId": "eq0ug0G2TQifitccs1zJRw",
  "noteUrl": "https://api-gateway.cryptoxlab.workers.dev/api/hedgedoc/eq0ug0G2TQifitccs1zJRw",
  "directUrl": "https://hedgedoc.example.com/note-id"
}
```

## 🎓 重要教訓

### 教訓 1：Redirect 不是「錯誤」

**錯誤認知**：
- ❌ 302 redirect 是錯誤
- ❌ 只有 2xx 才是成功

**正確認知**：
- ✅ 302 redirect 是正常的 HTTP 響應
- ✅ 它告訴客戶端資源的新位置
- ✅ 這是 RESTful API 的標準模式（Post-Redirect-Get）

### 教訓 2：不同工具有不同的預設行為

**curl 的行為**：
- `curl URL`：跟隨 redirect（最多 50 次）
- `curl -i URL`：顯示 headers，但不跟隨
- `curl -L URL`：明確跟隨 redirect

**n8n 的行為**：
- 預設：自動跟隨 redirect
- 需要手動設置：不跟隨 redirect

### 教訓 3：問題診斷要分層

本案例的問題分為兩層：
1. **服務端（Gateway）**：需要正確處理 POST + body + redirect
2. **客戶端（n8n）**：需要正確設置不跟隨 redirect

**不能只解決一層**，兩層都要正確才能成功。

### 教訓 4：n8n 的選項名稱可能不同

不同版本的 n8n 可能使用不同的選項名稱：

| 功能 | 舊版本 | 新版本 |
|------|--------|--------|
| 返回完整響應 | Return Full Response | Include Response Headers and Status |
| 允許錯誤狀態碼 | Ignore Response Code | Never Error |

**建議**：閱讀文檔時，理解功能而非只記名稱。
